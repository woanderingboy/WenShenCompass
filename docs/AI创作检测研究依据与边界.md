# AI辅助创作风险检测：研究依据与产品边界

核验日期：2026-08-20

## 结论先行

当前没有一种只读最终文本、跨模型、跨语言、跨题材都可靠的“AI作者鉴定器”。检测结果应叫“AI辅助创作风险”或“AI风格信号”，不能叫“AI生成概率证明”，更不能凭单次分数直接拒稿。

原因包括：

- 人工改写、同义改写和翻译会显著改变检测特征。
- 不同模型、采样温度和题材的分布不同。
- 短文本证据不足。
- 类型化网文、人类模板写作、统一编辑风格也会表现出低多样性和重复结构。
- 非母语作者、语言表达简洁的作者可能被误报。
- 困惑度、概率曲率等方法通常依赖特定参考模型，并不等同于平台能判断作品来源。

## 参考研究

1. Mitchell et al., **DetectGPT: Zero-Shot Machine-Generated Text Detection using Probability Curvature**，arXiv:2301.11305，2023。
   - https://arxiv.org/abs/2301.11305
   - 使用概率曲率进行零样本检测，依赖可访问的概率模型与分布假设。

2. Bao et al., **Fast-DetectGPT: Efficient Zero-Shot Detection of Machine-Generated Text via Conditional Probability Curvature**，arXiv:2310.05130，2023。
   - https://arxiv.org/abs/2310.05130
   - 对曲率检测进行效率改进，但依然不是不受模型、域和改写影响的来源证明。

3. Hans et al., **Spotting LLMs With Binoculars: Zero-Shot Detection of Machine-Generated Text**，arXiv:2401.12070，2024。
   - https://arxiv.org/abs/2401.12070
   - 通过两个语言模型的交叉困惑度关系进行检测，效果取决于模型选择及测试分布。

4. Sadasivan et al., **Can AI-Generated Text be Reliably Detected?**，arXiv:2303.11156，2023。
   - https://arxiv.org/abs/2303.11156
   - 讨论检测的理论与实践局限，以及改写对检测器的规避影响。

5. Wikipedia / WikiProject AI Cleanup，**Signs of AI writing**。
   - https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing
   - 属于社区观察总结，不是统计来源鉴定模型；适合构建可解释的编辑特征，不适合作为定罪证据。

## 本产品采用的检测层次

### 强信号

- AI助手对话残留
- 提示词、系统信息和生成参数残留
- 明确的“以下是续写内容”等元话语

这些信号可说明文本存在编辑疏漏或生成流程痕迹，但仍需核对其是否为剧情引用。

### 中弱风格信号

- 网文模板短语成组出现
- 连接词密度和公式化结构
- 泛化拔高、模糊归因、通用情绪动作
- 四字片段重复密度
- 句长、段长过度均匀
- 句首结构重复
- 破折号密度
- 局部用字多样性
- 不同文本区段的风险波动

这些只能说明“类似常见模型输出”，不能证明由AI生成。

## 产品决策

- 使用0—100“风格风险分”，而非伪装成统计概率。
- 同时显示风险档位和置信度。
- 短文本默认低置信度。
- 只出现弱信号时，置信度保持较低。
- 报告每项特征、加分和证据。
- 显示分段风险波动，帮助定位可能混入AI续写的区域。
- 报告固定展示误报和规避边界。
- 任何处罚或拒稿必须结合人工审查、版本历史、创作过程和平台声明。

## 后续提高准确性的正确方向

1. 经作者授权收集带真实来源标签的中文小说数据，覆盖不同题材和作者水平。
2. 测试多个模型、多个温度、纯AI、AI后人工改写和纯人工文本。
3. 数据按作者拆分训练集与测试集，避免把作者个人风格当成AI特征。
4. 分题材、分长度报告精确率、召回率和误报率。
5. 对低置信度结果只提示编辑复核，不输出来源结论。
6. 若生成平台支持可靠水印或内容凭证，优先使用来源凭证，而不是仅靠文本风格猜测。
