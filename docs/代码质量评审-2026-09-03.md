# 文审罗盘（wenshen-compass-mvp）代码质量 / 安全 / 可维护性评审报告

- **评审对象**：`D:/文审罗盘`（Node.js 原生实现，零运行时依赖，无构建）
- **评审范围**：`server.js`、`src/analyzer.js`、`src/aiStyleDetector.js`、`src/aiDetectorApi.js`、`src/chapterAnalyzer.js`、`src/commercialQuality.js`、`src/recommendationReview.js`、`src/aiReviewer.js`，并与 `README.md` 设计原则比对
- **评审方式**：仅静态阅读源码 + 比对 README；**未修改任何源码文件**
- **评审日期**：2026-09-03
- **严重度定义**：
  - **P0** = 可能导致安全/数据/正确性事故，需尽快修复
  - **P1** = 明显质量/可维护性/稳健性隐患
  - **P2** = 风格/优化建议

---

## 1. 总体评价

**架构清晰度：良好。** 项目遵循「纯函数检测引擎 + 单文件 HTTP 服务 + 纯静态前端」的分层，模块职责单一、可读性强，且严格践行了 README 声明的四条设计原则（可解释优先、合规/质量/推荐分层、不冒充平台、优雅降级）。检测引擎全部为可直接 `require` 的纯函数，配套 40 个 `node --test` 用例全绿，可测试性优秀。

**主要风险等级：1 个 P0（安全），其余为 P1/P2。**

最突出的问题是**外部 AI 检测服务的「脱敏」承诺未落地**：`README` 第 10 节明确写「送大模型/外部检测前会做脱敏与采样」，但 `src/aiDetectorApi.js` 的 `callExternalDetector` 只做了长度采样（`sampleLongText`），**没有对手机号 / 证件号 / 邮箱做任何脱敏**就直接 POST 给外部端点。而审稿大模型路径（`aiReviewer.js`）是正确脱敏的——两条外部通道行为不一致，且直接违反 README 约定，属于 P0 级隐私泄露风险（仅在配置了 `AI_DETECTOR_ENDPOINT` 时触发，但一旦发生即外发 PII）。

其余问题集中在：① 异常信息可能把外部端点 URL 回传前端（P1 信息泄露）；② `server.js` 的 `decodeURIComponent` 未加 try/catch，畸形 URL 可能抛出未捕获异常（P1 稳健性/潜在 DoS）；③ 工具函数与常量在多个模块重复定义（P1 可维护性）；④ 平台列表前后端硬编码耦合（P1 扩展摩擦）；⑤ 大量魔法数字与正则共享可变状态等（P2）。

整体而言，这是一个**结构健康、原则贯彻到位、但外部数据出口的隐私防护有缺口**的 MVP，修复成本很低，建议优先处理 P0 与安全相关的 P1。

## 3. 改进清单（按优先级排序）

### P0（最优先，安全）

**P0-1｜外部 AI 检测发送前未脱敏（隐私泄露）**
- **位置**：`src/aiDetectorApi.js` L53-69（`callExternalDetector`），尤其 L56 `sampleLongText(text, config.maxChars)` 与 L63 `body: JSON.stringify({ ..., text: sampling.text, ... })`。
- **问题**：文本（含手机号/证件号/邮箱）在配置 `AI_DETECTOR_ENDPOINT` 后**原样外发**给第三方，未做任何脱敏；与 `aiReviewer.js` L26/L29 的脱敏路径不一致，且违反 README §10 约定。
- **可执行建议**：
  1. 把 `aiReviewer.js` L18-23 的 `redact()` 抽到 `src/util.js` 并导出。
  2. 在 `callExternalDetector` 发送前对 `sampling.text` 脱敏：`const safeText = redact(sampling.text);` 再 `JSON.stringify({..., text: safeText, ...})`。
  3. 在 `runAIDetection` 返回里补一句 `warning` 说明「已脱敏后发送」。
  4. README §6/§10 保留「外部检测同样脱敏」声明或修正措辞。
- **影响面**：仅当启用外部检测时触发；修复改动约 10 行，零破坏性。

### P1（质量 / 稳健性 / 可维护性）

**P1-1｜异常信息回传导致外部端点泄露**
- **位置**：`src/aiDetectorApi.js` L90、`src/aiReviewer.js` L148。
- **建议**：降级 `warning` 使用固定中文文案（如「外部检测暂不可用，已降级为本地检测」），`error.message` 仅 `console.error` 记录到服务端，绝不进响应体。

**P1-2｜`decodeURIComponent` 未兜底，畸形 URL 可能崩溃**
- **位置**：`server.js` L66。
- **建议**：`let safePath; try { safePath = decodeURIComponent(req.url.split('?')[0]); } catch { return json(res, 400, { error: '请求路径无效' }); }`；并设 `safePath = safePath === '/' ? '/index.html' : safePath;`。

**P1-3｜工具函数/常量多副本（DRY 破坏）**
- **位置**：`clamp/mean/std` 见 `aiStyleDetector.js` L42-44、`commercialQuality.js` L3-5、`aiDetectorApi.js` L3；`WEIGHT` vs `LEVEL_COST` 见 `analyzer.js` L42 / `chapterAnalyzer.js` L5；`CHAPTER_HEADING` 见 `chapterAnalyzer.js` L4 / `commercialQuality.js` L1。
- **建议**：新建 `src/util.js` 导出 `clamp/mean/std/redact/excerpt/LEVEL_WEIGHT/CHAPTER_HEADING`，三处 `require` 复用；删除重复定义，补一个测试断言常量一致性。

**P1-4｜平台列表前后端硬编码耦合**
- **位置**：`analyzer.js` L1-7 `PLATFORM_PROFILES`、`public/index.html` 平台 checkbox 行、`aiReviewer.js` L1 依赖 `analyzer` 取 `name/note`。
- **建议**：抽 `src/platforms.js` 导出 `PLATFORM_PROFILES`；新增 `GET /api/platforms`（或并入 `/api/ai-detection/status`）返回平台 id/name 列表；`index.html` 改为动态渲染；`aiReviewer` 从 `platforms.js` 取元数据。消除三处漂移。

**P1-5｜逐章分析对每章跑完整 `analyzeNovel`（性能浪费）**
- **位置**：`src/chapterAnalyzer.js` L43。
- **建议**：新增轻量 `scanOnly(input)`（仅 `scan` + `analyzeCommercialQuality`），逐章复用；调用时显式传入 `recommendationMode:false` 避免每章跑推荐评审；章节报告不需要的全平台区间计算可跳过或按需。

## 4. 值得保留的优点（不要只挑刺）

1. **零依赖 + 纯函数引擎 + 40 用例全绿**：检测逻辑全部为可独立 `require`、可单测的纯函数，测试自包含（`test/fixtures` 随包分发），可维护性与可演进性极佳。
2. **分层职责清晰且互不冒充**：合规（`analyzer`/`chapterAnalyzer`）、成熟度（`commercialQuality`）、推荐价值（`recommendationReview`）、AI 风格（`aiStyleDetector`）、三角色审稿（`aiReviewer`）各自独立；README 明确「没违规 ≠ 写得好 ≠ 值得推荐」，代码也确实分层（质量类 RULES 不计入合规惩罚，见 `analyzer.js` L95）。
3. **优雅降级实现正确且显式标注**：外部检测/审稿模型未配置或失败均自动回退本地/离线，并在报告里写明 `mode: 'local'/'offline'` 与 `warning`（见 `aiDetectorApi.js` L83-92、`aiReviewer.js` L141-152），未让网络故障阻断主审核——符合 README 原则 4。
4. **令牌管理合规**：`REVIEW_MODEL_TOKEN` / `AI_DETECTOR_TOKEN` 仅经服务端 `Authorization` 头发送（`aiReviewer.js` L103、`aiDetectorApi.js` L62），`detectorStatus()` 只回传 `tokenConfigured: Boolean(...)`（`aiDetectorApi.js` L21），前端无任何 token/endpoint 字符串（已 grep 确认）。
5. **可解释优先贯穿全局**：每条 RULES 都带 `reason`+`advice`，AI 风格信号带 `evidence`+`explanation`+`advice`，推荐审核带 `reason`+`advice`；且 AI 分/区间均带明确免责声明（「非身份证明」「非官方通过率」）。
6. **正则状态 bug 已预防**：`scan()` 对 `g` 标志正则每次 `rule.re.lastIndex = 0`（`analyzer.js` L72）、`countPatterns` 同样重置（`aiStyleDetector.js` L48），避免了共享 RegExp 的 lastIndex 串扰。
7. **长文采样 + 覆盖率透明**：`sampleLongText` 24 窗均匀采样并回报 `coverage`（`aiStyleDetector.js` L28-40），外部调用也采样（`aiDetectorApi.js` L56），对超长文本有务实处理。
8. **路径穿越防护有效**：`server.js` L66-68 的 `path.normalize` + `startsWith(publicDir)` 对 `..` / 编码穿越实测可拦截（见 §2 分析），静态目录未越权暴露。
9. **脱敏在审稿路径正确**：`aiReviewer.js` 的 `makeReviewPacket` 对正文与 issue 片段均 `redact`（L26/L29），且回传前端时只给长度元信息（L151），不回吐脱敏后正文——这条外部通道是模范实现，应作为 P0 修复的参照模板。
10. **入口校验到位**：正文最少 20 字（`server.js` L29/L45）、请求体 25MB 上限（L25/L40）、`JSON.parse` 有 try/catch（L28/L44），基础健壮性有底线。
